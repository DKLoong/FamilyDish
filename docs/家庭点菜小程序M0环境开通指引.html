01直接答案：选仓库根目录

判断依据只有一个：所选目录里必须能看到 project.config.json。

在微信开发者工具里，目录选这一层
D:\WorkBuddy Workspace\PairBite

这是克隆下来的仓库根目录，里面同时有 project.config.json、miniprogram/ 和 cloudfunctions/。

D:\WorkBuddy Workspace\ 不要选（父目录）
└─ PairBite\ ✅ 选这一层
├─ project.config.json 判断依据
├─ miniprogram\ 不要选（子目录）
│ ├─ app.js / app.json / envList.js
│ └─ pages\ (11 个页面)
├─ cloudfunctions\ 必须被识别
└─ README.md / LICENSE / CLAUDE.md
为什么不能选 miniprogram/ 子目录？
根目录的 project.config.json 里写着两个相对路径：miniprogramRoot: "miniprogram/" 和 cloudfunctionRoot: "cloudfunctions/"。它们都相对项目根目录解析。
如果选了 miniprogram/，开发者工具会把它当成新项目根：云函数目录 cloudfunctions/ 找不到、cloudfunctionRoot 配置失效，还可能自动生成一个空的 project.config.json 覆盖现有配置，导致后面无法上传云函数。

02导入项目的 6 个步骤

用「导入项目」，不要用「新建项目」；不要生成任何快速启动模板。

  1. 打开微信开发者工具 → 左侧「小程序项目」→ 点击「导入项目」（或「+」里的导入）
    若已有项目列表，选择「导入项目」而非「新建项目」。新建项目会往目录里写模板文件。
  2. 「项目目录」选择 D:\WorkBuddy Workspace\PairBite
    选中后，工具通常会显示项目名 FamilyMenu，说明已读到根目录的 project.config.json。路径中的空格不影响编译。
  3. AppID 填或核对 wxe950e38570e065b9
    我已把这个 AppID 写入 project.config.json，导入后一般会自动带出，核对一致即可。不要点「测试号」：测试号不支持云开发。
  4. 项目名称随意，建议「家庭点菜」
    这只是开发者工具里的显示名，不影响代码。配置文件里的 projectname 已改为 FamilyMenu。
  5. 「后端服务」选「微信云开发」或「不使用云服务」均可
    这一项只影响是否立刻引导开通；导入后点工具栏「云开发」按钮照样能开通。不要勾选任何「建立普通快速启动模板」。
  6. 点击导入，然后做三项检查
    • 模拟器可以编译打开（首屏可能是原版 PairBite 的绑定页，正常）。
    • 目录树里同时看到 miniprogram/ 和 cloudfunctions/。
    • 右键 cloudfunctions 能看到「选择当前环境」等云函数菜单。
只要这三项检查通过，项目目录就选对了。 此时不需要 npm install、不需要上传云函数、不需要改任何业务代码。

03开通云开发，拿到环境 ID

这是 M0 唯一还需要你在微信侧完成的动作。

  1. 点击开发者工具顶部工具栏的「云开发」
    首次会要求同意服务协议并开通。若按钮灰色或提示「测试号不支持」，说明 AppID 是开发者工具测试号，需换成公众平台正式注册的小程序 AppID。
  2. 创建环境
    环境名称建议 family-menu-dev；计费按实际界面选择免费基础版 / 基础版即可。创建后系统会生成一个环境 ID，形如 cloud1-3gxxxxxxxx。
  3. 复制环境 ID，填入 PairBite/miniprogram/envList.js
    把占位符 your-env-id 替换掉即可，其余结构不要动：
    const envList = [{"envId":"cloud1-3gxxxxxxxx","alias":"cloud"}]
module.exports = {
    envList,
}
    miniprogram/app.js 里是 wx.cloud.init({ env: normalinfo[0].envId })，读取的就是数组第一项。当前已完成：cloud1-d4ggrforr7c833748 已写入并校验。
  4. 右键 cloudfunctions 目录 → 选择当前环境
    选中刚创建的环境。这个动作决定后续「上传并部署」落到哪个环境，M1 之前必须做一次。
  5. 在云开发控制台建集合（这一步我来做，需要你有控制台权限）
    新建 Family、UserFamily、ShoppingItem；连同 4 个旧集合共 7 个集合，权限全部统一设「仅管理端可读写」；前端不调用 wx.cloud.database()，读写均经 familyApi，不保留客户端直连旁路；按实施方案 4.3 建索引。

04订阅消息：已取消

首版不做订阅通知。本节保留仅为说明，不需要任何公众平台配置。

订阅消息、模板 ID、字段 DATA ID 全部不再需要。
一次性订阅按接收人逐条扣授权额度，与本项目「点菜人授权、其他成员接收」的结构冲突。S1 裁决后，首版改为记录页微信原生分享：纯前端、无模板、无云函数、无额度、无失败状态。
「消息推送 / 消息推送配置」（URL、Token、EncodingAESKey）属于客服消息回调，与发通知方向相反，本来也不需要，保持关闭即可。
体验成员：当前 2 个账号，够跑主链路与真机分享验证；3 类角色 × 2 个家庭的并行隔离测试改为串行轮换。建议后续补到 ≥5。
真机：≥2 台。分享卡片与落地页必须真机验证，开发者工具调用成功不等于链路可用。

05常见坑对照

现象原因处理
在「消息推送配置」里看到 URL / Token / EncodingAESKey 输入框把「客服消息回调」误当成「订阅消息模板」；前者方向是微信推给你的服务器，与发通知相反不要启用、不要填写；改到「功能 → 订阅消息 → 公共模板库」选模板
目录树里看不到 cloudfunctions/，或提示 cloudfunctionRoot 不存在选了 miniprogram/ 子目录，相对路径解析错位删掉该项目记录，重新用「导入项目」选 PairBite 根目录
导入后代码里多出模板页面 / project.config.json 被改写用了「新建项目」并勾选快速启动模板用 git status 检查；多余文件不提交，必要时用 git checkout -- project.config.json 恢复后再改 AppID
「云开发」按钮灰色或提示不支持用了开发者工具测试号，或该 AppID 未开通云开发确认 wxe950e38570e065b9 为公众平台正式注册小程序；在公众平台确认账号状态
提示 AppID 不匹配工具填写的 AppID 与 project.config.json 不一致统一为 wxe950e38570e065b9；以配置文件为准重新导入
编译报「找不到 envList / cloud 未初始化」envList.js 仍是 your-env-id按第 03 节回填环境 ID
路径含空格或中文导致异常个别旧版工具对路径敏感先升级开发者工具；仍异常再考虑迁到无空格路径，并告知我新路径
