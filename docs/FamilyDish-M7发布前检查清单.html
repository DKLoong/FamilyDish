05并发实测

CLI 无法调用云函数，需要你在小程序 Console 执行。目的：确认「同菜同餐次去重」的先查后写窗口是否真的会被撞破。

进任意页面，打开 Console，粘贴执行：

// 同菜同餐次并发点菜测试：两个请求同时发出
(async () => {
  const call = (data) => wx.cloud.callFunction({ name: 'familyApi', data })

  const list = await call({ collection: 'DishList', op: 'list', limit: 1 })
  const dish = list.result.data.items[0]
  if (!dish) return console.warn('没有菜品，先在首页导入示例菜')

  const stamp = Date.now()
  const mk = (tag) => call({
    action: 'placeOrder',
    payload: {
      dishId: dish._id,
      requestId: 'race' + tag + stamp,
      mealDate: '2026-11-09',
      mealType: '其他'
    }
  })

  const [a, b] = await Promise.all([mk('A'), mk('B')])
  console.log('A', a.result)
  console.log('B', b.result)

  const check = await call({
    collection: 'OrderList', op: 'list',
    filters: { status: 'pending' }, limit: 20
  })
  const same = check.result.data.items.filter(o =>
    o.dishId === dish._id && o.mealDate === '2026-11-09' && o.mealType === '其他')

  console.log('同键待做记录：', same.length, '条')
  console.log(same.length === 1
    ? '✅ 未触发竞态，两个请求合并为一条'
    : '⚠️ 竞态发生，生成 ' + same.length + ' 条重复记录')
})()
结果含义与下一步
1 条两个请求被正确合并（第二个读到第一个写入的记录并追加点菜人）。窗口存在但极难触发，维持现状，二期再做 dedupeKey
2 条竞态确认。需要加 dedupeKey：待做时写固定键、终态时写唯一随机值，配合唯一索引。这会新增一个索引，需你在控制台建
报错把 a.result / b.result 的完整内容发我

并发加入家庭不提供脚本。触发条件太苛刻：需要两个未加入的微信号，且家庭只剩 1 个名额，还要在同一秒内提交。 实际操作成本远高于收益，建议按「已知限制」记录，二期用计数字段或事务一并解决。

06真机回归

以下 6 条必须在手机上走，开发者工具通过不算数。
  1. 记录页圆形分享按钮 → 弹出微信「发送给」选择页，卡片标题为「家庭名 + 的点菜记录」
  2. 家人点开分享卡片 → 进入他自己的家庭，看不到你家菜单与记录
  3. 菜谱详情开始步骤计时 → 退到微信等 20 秒 → 回来，剩余时间正确减少
  4. 开飞行模式点菜 → 提示失败，不得假成功；恢复网络后可重试
  5. 三个角色分别登录 → 普通成员看不到「分类管理」「+ 新增」「成员角色」按钮
  6. 首页分类胶囊、菜谱表单候选、分类管理页 → 三者名称与顺序完全一致

07已知限制

限制影响处理计划
加入家庭名额校验非原子 极低 需两人同时加入且只剩 1 名额。二期用计数字段或事务收紧
同菜同餐次并发点菜可能重复建单 极低 见第 05 节实测。若实测为 1 条则维持现状，二期做 dedupeKey
分类重命名单次最多同步 100 道菜 很低 受云开发单次查询上限限制。家庭菜品通常远低于此，超出部分下次进分类页同步时不会自动改名，需手动调整
首版不支持份数与采购量缩放 设计内 二期按份数缩放，提示语方案已定稿（见需求文稿二期章节）
