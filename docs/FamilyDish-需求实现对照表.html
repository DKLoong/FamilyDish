01本次修复

核对发现的问题中，以下 4 项已在本会话修复，各有对应测试或文档改动。
已修复邀请码错误尝试限流

需求 3.4 要求限制频繁错误尝试。此前 INVITE_MAX_TRIES 只用于生成邀请码时避免碰撞，与加入失败次数无关。

现在 joinFamily 在码无效、格式错误或过期时按 openid 累计失败次数：10 分钟内达到 5 次即拒绝；加入成功后清零；满员不计入（不是猜码行为）。

实现：actions/family.js 的 assertNotThrottled / recordInviteFail / clearInviteFail。计数存在 User 文档，不新增集合。新增 12 项测试。
已修复加入家庭提示不带家庭名

需求 3.1 要求提示「你已加入家庭 X」。原返回「你已在一个家庭中」。

实现：alreadyInFamilyError(ctx) 统一生成提示并带上当前家庭名，创建家庭与加入家庭两处复用。
已修复首页缺「最近点菜记录」

需求 10.1 要求 MainPage 展示最近点菜记录。此前首页只有菜品列表。

现在首页顶部增加待做摘要：待做总道数 + 最近 2 条（菜名、点菜人、餐次），点击跳记录页。三人以上折叠为「A、B 等 3 人」。查询失败降级为空，不影响首页主流程。

实现：MainPage.load 并行拉取 + decoratePending + 顶部卡片。
已对齐文档两处实现优于文档的措辞

① 分享标题实际包含家庭名称（原文档写「固定标题」）；② 邀请链接只带邀请码、不带 familyId（原文档写两者都带）。两处实现都更合理，处理方式是改文档而非改代码。

已改：需求 8.2、3.4。

02已按选择实施

分类管理采用方案 ①，已实现并接入。
已实现分类管理（方案 ①）

分类是「名称 + 排序」的轻量标签，菜品上仍存分类文本，重命名时由服务端批量同步，所以不必迁移菜品数据。

支持新增、重命名、上下移动排序；不提供删除。首次进入分类页时自动把菜品里已存在但未登记的分类补入，避免空列表。同名校验、跨家庭校验、名称 1–12 字均在服务端。

首页分类顺序改为以分类表为准，表里没有的名称按菜品出现顺序追加作为兜底。

实现：actions/category.js（syncCategories / saveCategory / reorderCategories）、pages/CategoryManage、我的页入口。新增 22 项测试。

你已确认留到二期，与份数、并发去重同批处理。已记入风险清单。
