# FamilyDish · 家庭点菜小程序

一个面向家庭的小程序：多名成员共享菜品库、点菜记录与购物清单，谁点了菜、还缺哪些食材，一眼看清。

基于微信云开发，零服务器、零运维。不同家庭的数据自动隔离。

> 本分支由上游 [PairBite](https://github.com/630999Steven/PairBite)（作者 **630999Steven**，[CC BY-NC-SA 4.0](LICENSE)）改造而来。

**当前状态**：需求文稿、UI 标注稿 v1.2 与实施方案 v1.1 已定稿，但**业务代码仍是上游 PairBite 基线，改造尚未实施（M0 之前）**。以下功能与架构描述的是目标态，不是当前代码已实现的能力。实施计划见仓库外的《家庭点菜小程序实施方案.md》。

## 功能概览（目标态）

- **家庭管理**：创建或加入家庭、家庭名称、家庭内昵称、3 天有效邀请码、人数上限 10–50、创建者／管理员／普通成员三级角色、退出／移除／解散。
- **共享菜品库**：创建者与管理员手动录入，结构化食材（`name / quantity / unit / note`）、步骤与计时器、分类、归档、5 道自行整理的示例菜。
- **显式点菜**：进入菜谱详情不产生记录；点击「我要点这道菜」并确认后才生成。一条记录只含一道菜，状态为待做／已完成／已取消。点菜时保存菜品与点菜人昵称快照。
- **家庭记录**：状态筛选、完成与取消需二次确认、历史快照只读、终态不可变更。
- **购物清单**：按点菜记录独立存放食材来源、页面合并显示；整组标记已购买、手工添加、删除权限控制；取消点菜只移除该订单带入的食材。
- **随机选菜与食材搜索**：首版搜索食材，不搜索菜名。
- **分享告知**：记录页常驻圆形「分享」按钮，用微信原生转发把小程序发给家人。点菜成功提示「已点菜，可分享给家人」。

**首版不做订阅消息**（无模板、无额度账本）、**不做长截屏分享**、**不做多人协作编辑**。二期计划：多家庭切换、实时监听、营养计算、评论点赞、第三方菜谱导入。

上游基线界面截图保留在 `docs/images/` 下，展示的是改造前的绿色主题双人界面，**不代表 FamilyDish 界面**。当前 UI 以仓库外的 `family-menu-ui-prototype/design-spec.html` 为准。

## 技术栈

| 层 | 技术 | 说明 |
|---|------|------|
| 前端 | 微信小程序原生 | WXML + WXSS + JS |
| UI | WeUI + 暖木厨房设计令牌 | 主色 `#C9663B`，非上游绿色主题 |
| 后端 | 微信云函数 | Node.js + `wx-server-sdk ^2.6.3` |
| 数据库 | 微信云数据库 | NoSQL 文档数据库，7 个集合 |
| 存储 | 微信云存储 | 菜品图片，免费版经临时链接展示 |
| 通知 | 微信原生分享 | 首版不做订阅消息 |

无任何第三方 API 依赖，完全运行在微信云开发生态内。视觉风格为「暖木厨房」：低饱和米色底、白色卡片、主色点缀。

## 项目结构（目标态）

```
├── miniprogram/
│   ├── app.js                  # 全局家庭守卫与上下文
│   ├── app.json                # 4 入口 TabBar：首页 / 记录 / 购物 / 我的
│   ├── app.wxss                # 暖木厨房设计令牌
│   ├── envList.js              # 云环境配置
│   ├── components/             # family-guard、dish-card、order-sheet、empty-state
│   ├── utils/                  # api.js、dishSchema.js、shoppingGroup.js、timer.js
│   └── pages/                  # 首页 / 菜谱详情 / 点菜记录 / 购物 / 我的 + 管理与快照页
├── cloudfunctions/
│   ├── familyApi/              # 统一入口：白名单 CRUD + 领域动作 + 鉴权 + 事务 + 幂等
│   ├── ensureUser/             # 用户注册与家庭上下文
│   └── getFileURL/             # 云存储临时链接（沿用上游）
├── docs/images/                # 上游基线截图，仅历史参考
├── project.config.json         # 微信开发者工具配置
├── LICENSE
└── NOTICE.md                  # 改造说明（待补充）
```

基线的 11 个页面目录与 10 个云函数目录将在改造中停用或重写，具体映射见《实施方案》第 7 节。

**读写通道**：前端不调用 `wx.cloud.database()`。列表读取、详情读取与全部写操作都经 `wx.cloud.callFunction` 走 `familyApi`；7 个集合权限统一设为「仅管理端可读写」，不保留客户端直连旁路。

## 部署指南

### 前置条件

- 安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
- 注册一个微信小程序账号（[个人号即可](https://mp.weixin.qq.com/wxopen/waregister?action=step1&source=mpregister&token=&lang=zh_CN)），并在后台完成【小程序信息】和【小程序类目】填写（类目选 工具 → 备忘录 即可，并设为主营类目）
- **须为公众平台正式注册的小程序 AppID**。开发者工具里的「测试号」不支持云开发

> 下方截图来自上游部署流程，展示的是微信开发者工具界面，可能随工具版本变化。

### 第一步：获取源码

```bash
git clone https://github.com/630999Steven/PairBite.git
cd PairBite
git checkout -b family-v1
```

用微信开发者工具**导入项目**，目录选仓库根目录（含 `project.config.json` 的一层）。**不要选 `miniprogram/` 子目录**：`miniprogramRoot` 与 `cloudfunctionRoot` 都相对根目录解析，选错会导致云函数目录找不到。

### 第五步：上传云函数

在微信开发者工具中：

1. 选择环境

   ![image-20260426202731252](docs/images/image-20260426202731252.png)

2. 对云函数目录依次执行 →「上传并部署：云端安装依赖（不上传 node_modules）」

改造完成后只需部署 **3 个云函数**：

| 云函数 | 功能 |
|--------|------|
| `familyApi` | 统一读写入口：白名单 CRUD、领域动作、鉴权、事务、幂等 |
| `ensureUser` | 首次进入创建 `User`，返回家庭上下文 |
| `getFileURL` | `cloud://` 转临时链接 |

上游的 `getCoupleData`、`updateCoupleData`、`manageCategory`、`bindPartner`、`unbindPartner`、`updateKitchenName`、`sendNotify`、`getOpenId`、`createUser` 全部停用，须确保没有可调用的残留入口。其中 `getCoupleData` / `updateCoupleData` 允许前端传任意集合名与任意字段且无角色鉴权，是本次改造的首要安全缺口。

### 第六步：无需配置订阅消息

**首版不做订阅消息**。不需要申请模板、不需要字段 DATA ID、不需要配置模板环境变量。

告知家人改用微信原生分享：记录页的圆形「分享」按钮 + `onShareAppMessage`，纯前端能力，不调用云函数、不写数据库。成员点开卡片后，云函数按 `openid + UserFamily` 判定家庭归属；未加入家庭的新用户由全局守卫导入创建／加入流程。

> 公众平台里的「消息推送配置」（要填 URL / Token / EncodingAESKey）是客服消息回调，与订阅消息是两回事，本项目也不需要，保持关闭即可。

### 第七步：邀请体验成员（必做）

小程序未正式上线前，其他用户需被添加为**体验成员**才能访问：

1. [微信公众平台](https://mp.weixin.qq.com/) → 管理 → 成员管理 → 体验成员
2. 点击「添加」，输入对方微信号
3. 对方在微信中确认后，扫描体验版二维码即可使用

> 个人号最多可添加 15 名体验成员。不同家庭的数据通过 `familyId` + `UserFamily` 隔离，互不干扰。若只有 2 个账号，3 角色 × 2 家庭的并行隔离测试可降级为串行轮换角色。

### 第八步：上传代码并部署小程序

1. 点击微信开发者工具右上角「上传」，将代码上传为体验版（版本号随意），**无需提交审核上架**。
2. 管理 → 版本管理里选为体验版，之后扫描二维码即可进入（上一步被添加为成员的人才能扫码）。

## 使用流程（目标态）

1. **创建者**打开小程序 → 填写家庭名称（1–12 字）与家庭内昵称（1–20 字）→ 创建家庭。
2. 在「我的」生成邀请码（6 位字母数字，3 天有效，可多人使用）→ 转发给家人。
3. **家人**输入邀请码、填写昵称加入 → 共享同一份菜品库、记录与购物清单。
4. 首页选菜 → 菜谱详情勾选已准备食材 → 点「我要点这道菜」→ 在底部弹层确认（用餐日期／餐次／备注均选填）→ 生成待做记录，未勾选的食材进入购物清单。
5. 记录页点右下圆形「分享」按钮，把小程序转发给家人；完成或取消点菜需二次确认。

## 数据库说明

| 集合 | 用途 | 隔离 / 写入 |
|------|------|---------|
| `User` | 用户身份存根，`_id = openid` | `ensureUser` |
| `Family` | 家庭主体、状态、人数上限、邀请码 | 领域动作 |
| `UserFamily` | 权威成员关系、角色、家庭内昵称 | 领域动作 |
| `DishList` | 菜品与菜谱 | `familyId`，白名单 CRUD |
| `Category` | 菜品分类 | `familyId`，白名单 CRUD |
| `OrderList` | 点菜记录与菜品快照 | `familyId`，仅领域动作 |
| `ShoppingItem` | 购物来源记录 | `familyId`，白名单 CRUD + 领域动作 |

云函数用 `cloud.getWXContext()` 取 `openid`，查 `UserFamily` 得有效 `familyId` 与 `role`，再按动作查权限表。`familyId`、点菜人、角色、时间戳、状态变更一律由服务端写入；`Family.memberOpenids` 仅供展示，不得作为鉴权依据。

|------|---------|

## 常见问题

**Q：必须多人才能用吗？**
A：不需要。单人可创建家庭并完整使用菜品、点菜与购物清单功能；只是分享出去前没有其他接收人。

**Q：如何退出家庭或解散家庭？**
A：普通成员与管理员可主动退出，创建者不能直接退出、只能解散（需二次确认）。退出、被移除或解散后只失去后续访问权限，历史点菜记录保留；解散首版只标记「已解散」并阻断访问，不物理删除数据。

**Q：家人看不到我上传的图片？**
A：免费套餐下云存储权限无法改为「所有用户可读」，项目通过 `getFileURL` 云函数把 `cloud://` 文件 ID 转为临时链接实现互看。临时链接有效期约 2 小时（前端缓存 1.5 小时自动续期），长时间停留页面不刷新可能出现图片失效，刷新即可恢复。若已升级付费套餐，可将云存储权限改为「所有用户可读」以简化链路。

**Q：点菜后家人会收到微信通知吗？**
A：不会。首版已移除订阅消息，改用记录页「分享」按钮手动转发小程序卡片。这是一次产品取舍：一次性订阅额度按接收人记账，点菜人授权无法替其他成员积累额度，送达率不可控。

**Q：云函数部署报错怎么办？**
A：先在云函数目录下执行 `npm install`，再上传部署。若仍报错，检查 Node.js 版本与 `wx-server-sdk` 版本是否匹配。

**Q：为什么代码里还是 `coupleId` 和绿色主题？**
A：因为改造尚未实施。本 README 描述的是定稿目标态；基线代码与本文档不一致是预期状态，请以《实施方案》M0–M7 的顺序推进。
